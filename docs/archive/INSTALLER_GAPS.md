## Intentional Gaps

### 1. Database Architecture (SQLite Preference)
Maestro v2 prioritizes a "Zero Infrastructure" setup. While `wizard.py` heavily supports PostgreSQL (via Docker or Embedded), Maestro defaults to **SQLite with WAL mode**.
- **Reasoning:** Reduces installation friction and eliminates Docker dependencies.
- **Future Plan:** A hybrid DuckDB+SQLite approach is planned to replace PostgreSQL entirely while providing analytical power.

### 2. Dependency Management (`uv` vs `pip/go`)
`wizard.py` requires `uv` for all operations. Maestro supports `pip` for Python components and `go` for high-performance TUI/Search components.
- **Reasoning:** Leverage Go for performance-critical tools like Zoekt and the TUI.

## Future Work (The "Roadmap")

The following gaps are targeted for implementation in upcoming sub-tracks:

1. **MCP Server Setup (Task 1.4):** Integration of `mcp.json` installation and path validation.
2. **Container Runtime Detection:** Adding checks for Docker/Podman to support containerized workflows.
3. **TLDR CLI Integration:** Option to install the `llm-tldr` tool for advanced code analysis.
4. **Interactive API Key Configuration:** Prompting for Perplexity, Braintrust, and other service keys during install.
5. **Update Wizard:** A self-update mechanism to pull latest Maestro components without full reinstall.
